# Architecture

## Stack

| Concern   | Choice                                                | Notes                                                                  |
| --------- | ----------------------------------------------------- | ---------------------------------------------------------------------- |
| Framework | **Astro 7** (`7.3.5`)                                 | Static-first, island-free content site.                                |
| Styling   | **Tailwind CSS v4** (`4.3.3`) via `@tailwindcss/vite` | Design tokens as CSS variables / `@theme inline`.                      |
| Adapter   | **`@astrojs/cloudflare`** (`14.3.3`)                  | `output: 'static'`, `session: false`, `imageService: 'compile'`.       |
| i18n      | **Astro built-in i18n layout** + `src/i18n/ui.ts`     | English enabled; `si`/`ta` structured but off.                         |
| Fonts     | **Fontsource variable**, self-hosted                  | Elegant serif display + clean sans body (+ Noto Sinhala/Tamil stacks). |
| SEO       | **`@astrojs/sitemap`** (`3.7.4`)                      | Enabled only when `indexable` is true.                                 |
| Content   | **Astro Content Collections** + Google Sheet          | Services/categories/pages in `src/content/*`; live prices from Sheet.  |
| Runtime   | **Cloudflare Workers**                                | Git-connected Workers Builds; static assets.                           |
| Toolchain | **Node 22**, **pnpm 12**, **TypeScript 6**            | See `DECISIONS.md` D-S02.                                              |

### Build output (Astro 7 + adapter v14)

- `astro build` emits static assets to `dist/client/`; `dist/server/` is empty for
  this all-static site.
- The adapter generates `dist/client/wrangler.json` plus a `.wrangler/deploy/config.json`
  redirect, so `wrangler deploy` from the repo root uses the generated config. The
  root `wrangler.jsonc` only needs `name`, compatibility settings, `main`,
  `assets.not_found_handling`, and optional bindings.
- `session: false` avoids provisioning a session KV namespace.
- `imageService: 'compile'` optimizes imported content images at build time
  (Sharp → WebP variants) without needing the Cloudflare Images binding. The
  full-bleed hero uses pre-sized WebP via plain `<img>`/CSS.
- Dev and preview run on the real `workerd` runtime.

## Static vs on-demand

All pages are prerendered, including `robots.txt.ts`. There are **no** on-demand
routes, no bindings, no database and no email. Appointments are WhatsApp-only by
design. Sheet data is fetched either in the browser (runtime) or at build time
(build), never by a request-time server.

## Configuration surface (`src/data/site.ts`)

Single source of truth per salon. Components read from here and from content —
never hardcode brand/phone/currency/prices.

```ts
export type Locale = 'en' | 'si' | 'ta';
export type LocalizedText = { en: string; si?: string; ta?: string };

export const site = {
  name: 'Amara Studio',
  tagline: { en: 'Hair, skin and nails — beautifully done.' },
  logo: '/logo.svg',
  whatsappNumber: '94770000000',        // digits only, country code, no "+"
  phone: '+94 77 000 0000',
  email: '',                             // display only; requests go to WhatsApp
  address: { en: '24 Ward Place, Colombo 07, Sri Lanka' },
  mapEmbedUrl: '…&output=embed',
  mapLink: '…',
  hours: [ { day: 1, open: '09:00', close: '19:00' }, … ], // 0 = Sunday
  socials: { facebook: '', instagram: '', tiktok: '' },
  defaultLocale: 'en',
  locales: ['en'],                       // add 'si'/'ta' when translated
  appointment: {
    minLeadDays: 0,                      // earliest selectable preferred day
    maxLeadDays: 60,                     // latest selectable preferred day
    slots: ['09:00', '10:00', '11:00', '12:00', '14:00', '15:00', '16:00', '17:00'],
  },
  services: {
    mode: 'runtime' as 'runtime' | 'build',
    sheetId: '',                         // empty = run from content collections
    sheetTab: 'Services',
    refreshMinutes: 5,
  },
  indexable: false,
  siteUrl: 'https://demo-salon.zuvo.lk',
  currency: { code: 'LKR', symbol: 'Rs.' },
  heroVariant: 'overlay' as 'classic' | 'split' | 'overlay',
} as const;
```

## Content model (`src/content.config.ts`)

```ts
const localizedText = z.object({
  en: z.string(),
  si: z.string().optional(),
  ta: z.string().optional(),
});

const services = defineCollection({
  loader: glob({ pattern: "**/*.md", base: "./src/content/services" }),
  schema: z.object({
    category: z.string(), // category id
    name: localizedText,
    description: localizedText.optional(),
    duration: z.number().int().positive().optional(), // minutes
    price: z.number().nonnegative(), // LKR
    available: z.boolean().default(true),
    featured: z.boolean().default(false),
    order: z.number().default(0),
    image: z.string().optional(),
  }),
});

const categories = defineCollection({
  loader: glob({ pattern: "**/*.md", base: "./src/content/categories" }),
  schema: z.object({
    name: localizedText,
    order: z.number().default(0),
    image: z.string().optional(),
  }),
});

const pages = defineCollection({
  loader: glob({ pattern: "**/*.md", base: "./src/content/pages" }),
  schema: z.object({ title: z.string() }),
});
```

The **service file name (without `.md`) is the stable id** that matches rows in the
owner's Google Sheet, so renames must be deliberate. See
`docs/CONTENT-AND-SERVICES.md`.

## Data flow

```
content collections ─┐
                     ├─▶ lib/services.ts ─▶ pages/components ─▶ HTML
Google Sheet (live) ─┘          │
                                └─▶ client estimator (runtime mode)
```

- `lib/services.ts` is the only place that knows about both sources. It merges
  collection data with Sheet overrides by id (price/available), groups by category,
  and exposes query helpers (`getServices`, `getCategories`, `getFeatured`).
- In `runtime` mode, `BookPage`/`Estimator` receive a serialized service list and a
  small client script re-fetches the Sheet in the browser to refresh price/
  availability; failures fall back to the build-time values.
- In `build` mode (production clones), `scripts/fetch-services.ts` fetches the Sheet
  during `prebuild` and writes `src/data/services-live.json`; the site is fully
  static and the Sheet is never requested at runtime.

## i18n strategy

- Astro i18n is configured with `defaultLocale` and `locales: [...site.locales]`,
  `prefixDefaultLocale: false`. English is served at `/`; enabling `si`/`ta` adds
  generated `/si/…` and `/ta/…` routes with no component changes.
- All UI strings live in `src/i18n/ui.ts` in parallel `en`/`si`/`ta` objects.
  `useTranslations(locale)` is typed against `en`, so missing `si`/`ta` keys fall
  back to English at runtime and structural drift is a type concern.
- Long-form page copy is one Markdown file per locale under
  `src/content/pages/<page>/<locale>.md`; localized content fields use
  `LocalizedText`.
- `localizedPath(path, locale)` / `switchLocalePath(pathname, target)` build links;
  `LangSwitcher` links to the same page in every enabled locale and is hidden when
  only one locale is enabled.
- `BaseLayout` emits `hreflang` alternates and `og:locale` for every enabled locale.
- WhatsApp pre-filled messages and the appointment message are localized.

## Theming

Tokens live in `src/styles/theme.css`; `global.css` maps them to Tailwind via
`@theme inline`. A clone rebrands by editing token values (and preset overrides)
only.

| Token                | Demo value | Use                           |
| -------------------- | ---------- | ----------------------------- |
| `--c-bg`             | `#FAF6F2`  | Warm cream page background    |
| `--c-surface`        | `#FFFFFF`  | Cards                         |
| `--c-surface-alt`    | `#F4EBE4`  | Subtle section background     |
| `--c-text`           | `#2B2320`  | Primary text (soft charcoal)  |
| `--c-text-muted`     | `#7A6A63`  | Secondary text                |
| `--c-primary`        | `#B76E79`  | Rose accent — buttons, links  |
| `--c-primary-strong` | `#9C5561`  | Primary hover                 |
| `--c-accent`         | `#7C8C6A`  | Muted sage — badges, eyebrows |
| `--c-border`         | `#E7DAD2`  | Hairline borders              |
| `--font-heading`     | "Fraunces" | Elegant serif display         |
| `--font-body`        | "Inter"    | Clean sans body               |

Utilities: `bg-bg`, `bg-surface`, `text-text`, `text-text-muted`,
`border-border`, `bg-primary`, `text-primary`, `bg-accent`; `font-heading`,
`font-body`. Radius is soft (`--radius-md`), shadows minimal. Reusable classes:
`.eyebrow`, `.btn-primary`, `.btn-secondary`, `.card`.

Fonts are loaded via Fontsource variable; both stacks include Noto Sans Sinhala and
Noto Sans Tamil so Indic text renders correctly once translations are enabled.

## Components

- `Header` — logo, primary nav (Services, Book, Gallery, About, Visit), WhatsApp
  CTA, `LangSwitcher`.
- `Footer` — brand, nav, socials, hours summary, copyright.
- `Hero` — brand/tagline, primary CTA (Book), secondary (View services), featured
  imagery.
- `services/*` — category nav, service list/cards with price + duration,
  availability badge, featured strip.
- `book/Estimator` — select services, running indicative total; `DateTimePicker` —
  native date input + preferred slot choices; `StickyBookBar` — mobile summary +
  Book on WhatsApp; `BookButton` — inline CTA.
- `gallery/GalleryGrid`, `visit/*`, `pages/*` compose the pages.
- Guidelines: semantic HTML, accessible labels/focus states, mobile-first, no
  hardcoded brand values, no client framework islands.

The only shipped JavaScript is `src/scripts/appointment.ts` (estimator total,
selection state, message assembly) plus a tiny inline mobile-menu toggle. Both
degrade gracefully without JS (the Book page still offers a generic WhatsApp link).

## WhatsApp links

`src/lib/whatsapp.ts` exports `buildWhatsAppLink(message: string)`:

```ts
const n = site.whatsappNumber.replace(/[^0-9]/g, "");
return `https://wa.me/${n}?text=${encodeURIComponent(message)}`;
```

Every CTA routes through it. The appointment message is assembled in
`src/lib/appointment.ts` (see `docs/APPOINTMENT-FLOW.md`). Never inline `wa.me`
URLs in components.

## SEO & structured data

- `BaseLayout` emits `<title>`, meta description, canonical (`Astro.url` /
  `site.siteUrl`), OG/Twitter tags and `og:image`.
- `@astrojs/sitemap` is added only when `site.indexable` is true.
- JSON-LD: `BeautySalon`/`HairSalon` `LocalBusiness` with name, address, phone,
  hours and `areaServed`; `Service` items where useful.
- `404.astro` + `assets.not_found_handling: "404-page"` in `wrangler.jsonc`.

## Indexing

`site.indexable` drives `BaseLayout` (`<meta name="robots">`) and
`robots.txt.ts`; `public/_headers` sends `X-Robots-Tag: noindex` on the demo.
The demo ships `false`; clones flip all three. See `docs/CUSTOMIZATION.md`.
